# Скрипт-магазин Skystore на Django

Простой и удобный веб-интерфейс для демонстрации, хранения и продажи ваших плагинов, утилит и примеров программного кода, дополненный полноценным блогом проекта и безопасной системой управления доступом. Проект разработан в рамках практического задания по основам веб-разработки на Django.

## 🚀 Реализованный функционал

### 📦 Каталог товаров (Приложение `catalog`)
- **Полный цикл CRUD:** Реализован законченный механизм управления продуктами на базе Class-Based Views (`ListView`, `DetailView`, `CreateView`, `UpdateView`, `DeleteView`).
- **Главная страница (Каталог):** Динамический вывод списка доступных продуктов из базы данных PostgreSQL со строго настроенной сортировкой по убыванию ID. Реализована встроенная постраничная навигация (пагинация) средствами CBV по 3 товара на страницу.
- **Умная фильтрация каталога:** На уровне контроллера `ProductListView` и `ProductDetailView` настроена динамическая проверка прав:
  - Неавторизованные гости видят исключительно опубликованные товары (`is_published=True`).
  - Авторизованные пользователи видят все опубликованные товары, а также свои собственные скрытые публикации.
  - Администраторы и модераторы имеют полный доступ к просмотру всего перечня товаров для проверки.
- **Детальная страница товара:** Просмотр полной информации о конкретном плагине (включая название, цену, изображение и описание) по валидному URL-адресу `/products/<int:pk>/`. Реализован безопасный возврат в каталог с поддержкой пространств имён (`catalog:home`).
- **Страница контактов:** Контактные данные организации. Форма обратной связи обрабатывается контроллером через POST-запрос, логирует обращения в консоль сервера и выводит Bootstrap-уведомление об успешной отправке.
- **Форма добавления и редактирования товара (`ProductForm`):** 
  - Реализована на базе защищенного класса `forms.ModelForm` с автоматической стилизацией всех полей (внедрение CSS-классов Bootstrap 5 через метод `__init__`).
  - **Антиспам-фильтр (Валидация):** Встроена серверная проверка на уровне полей `name` и `description`, блокирующая сохранение продуктов с запрещенными словами в любом регистре (*казино, криптовалюта, крипта, биржа, дешево, бесплатно, обман, полиция, радар*).
  - **Валидация цены:** Метод `clean_price` гарантирует, что стоимость продукта не может быть отрицательной, и выводит понятное пользователю предупреждение.
  - **Загрузка и валидация изображений (Дополнительно):** Реализован механизм загрузки логотипов и обложек с жестким ограничением формата (только **JPEG** и **PNG**) и объема файла (не более **5 МБ**).

### 🔐 Ролевая модель и разграничение прав (Новое ✨)
- **Контроль владения (Owner):** К модели продукта добавлено поле `owner`, связывающее товар с конкретным пользователем (`settings.AUTH_USER_MODEL`). При добавлении нового продукта через `ProductCreateView` автор привязывается автоматически на основе текущей сессии (`form.instance.owner = self.request.user`).
- **Защита от чужого редактирования:** Контроллер `ProductUpdateView` проверяет автора записи. Если неавторизованный или сторонний пользователь попытается отредактировать чужой продукт (в том числе через прямую подмену ID в URL), система заблокирует операцию и сгенерирует исключение `PermissionDenied` (ошибка **403 Forbidden**).
- **Роль «Модератор продуктов»:** Внедрена система ручного модерирования контента из-за наплыва пользователей:
  - К модели продукта добавлено поле статуса публикации `is_published` (`BooleanField`, по умолчанию `False`).
  - Добавлено кастомное разрешение в класс `Meta` модели `Product` — **`can_unpublish_product`** («Может отменять публикацию продукта»).
  - Модератор наделен правами отменять публикацию и удалять любой продукт платформы. При этом он защищен от изменения критических данных (цена, название, описание), так как для него выделено урезанное представление `ProductModerationView` на базе специализированной формы `ProductModeratorForm`.
- **Динамический интерфейс шаблонов:** Кнопки управления в файлах `home.html` и `product_detail.html` полностью инкапсулированы в логические блоки:
  - Кнопка *«Редактировать»* отображается **строго владельцу** товара.
  - Кнопка *«Модерация статуса»* отображается **только пользователям с разрешением** `can_unpublish_product`.
  - Кнопка *«Удалить»* отображается **владельцу товара ИЛИ модераторам** с системным правом `delete_product`.

### 📝 Блог проекта (Приложение `blog`)
- **Полный цикл CRUD:** Реализовано отдельное приложение для ведения блога на базе веб-дженериков (Class-Based Views).
- **Фильтрация контента:** На уровне контроллера `BlogPostListView` настроена автоматическая фильтрация — отображаются только те статьи, которые имеют положительный признак публикации (`is_published=True`).
- **Умный счётчик просмотров:** При каждом открытии детальной страницы статьи счётчик просмотров автоматически увеличивается на 1.
- **Email-нотификации:** Реализована автоматическая отправка поздравительного письма на почту администратора с помощью встроенного почтового клиента `django.core.mail.send_mail` в момент, когда публикация набирает ровно 100 просмотров.
- **Динамический редирект:** После успешного редактирования статьи через `UpdateView` пользователь перенаправляется на страницу детального просмотра именно этой статьи.

### 👤 Пользователи и профили (Приложение `users`)
- **Кастомная модель пользователя:** Реализован класс `User` на базе `AbstractUser`. Авторизация перенастроена со стандартного `username` на уникальный **Email**. Модель расширена дополнительными полями: *аватар (изображение), номер телефона, страна*.
- **Система аутентификации:** Разработаны полноценные механизмы регистрации, авторизации (входа) и выхода из системы с использованием кастомных Bootstrap-стилизованных форм.
- **Email-нотификации гостям:** Интегрирована автоматическая отправка приветственного письма на электронную почту пользователя сразу после успешного создания учётной записи.
- **Разграничение прав доступа:** Интегрирован миксин `LoginRequiredMixin`. Доступ к страницам создания, редактирования и удаления товаров полностью закрыт для анонимных пользователей. 
- **Кастомный профиль:** Реализован личный кабинет пользователя с возможностью динамического редактирования персональных данных и загрузки аватара.

### 🎨 Архитектура и интерфейс
- **Bootstrap 5:** Вся визуальная часть, включая формы каталога, формы модерации и личного кабинета, полностью адаптирована и стилизована.
- **Декомпозиция шаблонов:** Выделен главный базовый шаблон `base.html` и изолированный подшаблон меню навигации `catalog/includes/menu.html` для исключения дублирования разметки. Контекстно зависимое меню динамически скрывает и отображает кнопки («Добавить товар», «Профиль», «Войти», «Регистрация») на основе статуса авторизации `user.is_authenticated`.

## 🛠 Технологический стек

- **Python** (версия 3.14)
- **Django** (версия 6.1+)
- **PostgreSQL** (полноценная реляционная СУБД)

## 💻 Инструкция по локальному запуску проекта

Для запуска проекта на своем компьютере выполните следующие шаги по порядку:

### 1. Клонирование репозитория и переход в папку
```bash
git clone <ссылка_на_ваш_репозиторий>
cd homework_basics_django
```

### 2. Настройка переменных окружения (`.env`)
В корневой директории проекта создайте файл **`.env`** (на основе образца `.env.sample`) и заполните его доступами к вашей локальной базе данных PostgreSQL:
```env
SECRET_KEY=ваша_секретная_строка_django
DEBUG=True
DB_NAME=имя_вашей_базы_данных
DB_USER=postgres
DB_PASSWORD=ваш_пароль_от_postgres
DB_HOST=localhost
DB_PORT=5432
```

### 3. Установка зависимостей через Poetry
Проект использует менеджер пакетов Poetry 2.0+ с отключенным режимом упаковки (`package-mode = false`). Разверните окружение командой:
```bash
poetry lock
poetry install
```

### 4. Применение миграций и инициализация ролей
Создайте структуру таблиц для каталога, блога и новой системы пользователей в PostgreSQL, после чего запустите кастомную команду для автоматического развертывания ролей и прав доступа:
```bash
poetry run python manage.py migrate
poetry run python manage.py create_groups
```

### 5. Загрузка демонстрационных данных и создание Администратора
```bash
poetry run python manage.py fill_db
poetry run python manage.py createsuperuser
```

### 6. Запуск сервера разработки
Запустите встроенный локальный сервер Django:
```bash
poetry run python manage.py runserver
```

### 7. Проверка работы в браузере
После успешного запуска перейдите по адресам:
- Главная страница каталога: [http://127.0.0](http://127.0.0)
- Раздел публикаций (Блог): [http://127.0.0blog/](http://127.0.0blog/)
- Личный кабинет (Профиль): [http://127.0.0users/profile/](http://127.0.0users/profile/)
- Форма регистрации: [http://127.0.0users/register/](http://127.0.0users/register/)
- Панель администратора Django: [http://127.0.0admin/](http://127.0.0admin/)
